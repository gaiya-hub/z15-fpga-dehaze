# 双 ARM 正式演示版本

2026-10-28：将已上板验证的双 ARM 统计方案接入正式单图和批量处理入口。原 FPGA 位流、模型权重和定点去雾算法保持一致。

## 启动

关闭旧演示窗口，重新双击项目根目录的 `launch.cmd`，初始化板卡，选择图片后处理。新窗口标题含“V3双核版”；新结果显示“ARM双核统计”或“ARM单核统计（尺寸回退）”。历史记录保留原执行方式，不因更换固件变成双核数据。

CPU0 先准备非缓存共享描述符，调试器确认本次启动标记后启动 CPU1。每张图片开始前复位 CPU1，并清除旧标记；每张图片完成后停止 CPU1。固件与启动信息按 SHA256 校验。旧版暗通道/V2模式保持单核并跳过双核初始化。

## 计算与正确性

两个 Cortex-A9 使用私有 16 行环形缓存，以全图坐标处理上下分区，保留 15×15 反射边界。满足对齐条件时使用双核；像素数不能被8整除、高度小于16或无合适分界时回退 ARM0。FPGA仍完成暗通道、导向细化、32路Q14神经推理和失真保护。

试验版原版—双核—原版实测：640×360从496.89降到483.33 ms，548×412从487.38降到473.98 ms，1920×1280从5281.78降到5144.24 ms。完整板上稳定计算时间缩短约2.6%–2.8%，不是两倍加速。局部统计约快29%，部分收益被缓存维护抵消；不能保证比电脑快。

5个边界尺寸对全部19项局部特征核对一致；3张常用/最大尺寸的最终输出与独立定点参考、前后单核版逐像素一致。发布固件和正式入口另外实测，记录见 `DUAL_ARM_DEPLOYMENT.json`。这些不是全134对数据集的双核上板测试。

## 时间口径

“算法合计”＝电脑帧参数＋板卡暗通道、局部统计、神经、保护、DDR及缓存控制与双核作业同步。逐图双核启动握手和CPU1启动等待单列，不计入稳定算法耗时；包含在全流程等待中。JTAG上传/回读另列。同算法对比不把启动或传输隐藏成算法加速收益。

图片输出不变，PSNR/SSIM/MAE保持一致；切换双核不提高SSIM。本版仍通过JTAG逐张传输，没有新增SD卡独立批处理、视频或功耗数据。

## 构建与恢复

运行 `python -B build_firmware.py` 同时编译 `main.c` 与 `dual_entry.S`，从生成的ELF提取CPU1入口，并生成 `board/firmware_protocol.json`。必须把 `demo.elf` 与对应启动信息一起更新；不复用试验版固定入口地址。无需重新综合FPGA位流。

切换前的正式源码、固件、说明和本地开源源码已逐文件备份，备份位置和哈希见部署记录中的backup字段。恢复时应同时恢复固件、启动代码与界面源码，而不只覆盖一个ELF。
