# SD＋串口版操作说明

已选择第一阶段：JTAG只在本批开始时配置一次硬件/程序并启动CPU1；图片从板上SD读取，结果写回SD。串口显示进度，处理结束后通过读卡器导入完整结果。不是SD上电自启动，也没有网口回传。

## 当前验证范围

- 新硬件100MHz时序通过：WNS +0.359 ns、WHS +0.036 ns；LUT38969/46200、DSP156/160、BRAM44.5/95。SD0位于PS MIO，不增加去雾计算模块。
- 新XSA生成独立xilffs BSP，SD批处理固件编译通过；CPU1入口由当前ELF自动提取并校验固件/位流SHA256。
- 新SD硬件上的3张JTAG图像回归逐像素一致，覆盖常用图、双核小图及单核回退。该检查验证新增配置不破坏原去雾功能，不等于SD图片读写实测。
- 实板启动SD固件返回0x53440001（卡挂载失败），缺卡保护已检查。随后已重新加载并验证正式双核版本。
- 10项离线协议测试通过；C/Python CRC32交叉检查通过；隐藏界面导入渲染和共享板卡锁检查通过；15项已有软件测试通过。离线数据明确标记SIMULATED，不作为实卡证据。
- 已完成两图真实SD读取、写回、串口与最终原始输出核验；修正后的整批计时为5.216秒。范围仅为这两张图，详见SD_ACCEPTANCE.md。原JTAG双核版本保留。

## 卡准备好后的首次操作

1. 准备已备份数据的FAT32 microSD/TF卡和读卡器。首轮仅用两张图片，先不要跑大量数据。
2. 将 `prepared_tasks/demo2/DEHAZE` 整个目录复制到卡根目录，形成 `卡根目录/DEHAZE/INDEX.BIN`、`IN/`、`OUT/` 和 `TASK.JSON`。OUT此时应为空。程序不会格式化卡，也不会覆盖已有输出。
3. 安全弹出读卡器，开发板断电后插卡。保持当前可JTAG运行的启动拨码，不切换SD启动；这阶段没有BOOT.BIN。
4. 接好板卡电源、JTAG及PS_UART USB线，上电。打开本版 `launch_sd.cmd`，点击顶部“SD任务 / 结果”。原正式版仍从原launch.cmd运行。
5. 选择PS_UART对应的COM口，连接115200串口。可通过USB线拔插和“刷新”识别，不能把蓝牙COM口当板卡串口。
6. 点击“一次初始化并启动SD批处理”。等待串口 `SD_BATCH_DONE`，或“查询完成状态”明确提示完成；运行时主界面板卡操作被锁住。
7. 完成后断电取卡，用读卡器接电脑，点击“导入SD完整结果”，选择卡上的DEHAZE目录。结果原始像素保留并与独立定点参考核验，随后在原三图/质量/电脑同算法页面显示。
8. 首轮实卡验证通过后，再导出自己的图片文件夹。目标已有DEHAZE任务时先保留旧任务并选择其他空目录。首版不支持中断续跑或覆盖旧输出；已完成记录可部分导入。

## 界面与计时

SD卡处理期间界面只显示串口进度，完整图片在导入后显示。三个图、放大、PSNR/SSIM/MAE和电脑同算法比较继续保留；GT仅用于评价，不参与去雾。

电脑先完成图片解码、缩放、空气光/融合权重/帧参数估计，导出二进制。板卡运行时独立读SD计算并写出结果；不是直接把任意JPG扔进卡里就能全部由板卡处理。

算法合计为帧参数计算加板上稳定计算。另列SD读取＋输入校验、输出写入、输出CRC、首图预热及CPU1启动。每批仅首图预热一次，其余图片复用已启动CPU1。

每图R文件给出读入开始至输出写完、最终记录写入前的时间。BATCH.BIN给出SD挂载、索引读取、CPU1等待、预热、所有图片计算、读写、逐图记录和串口进度的整批时间；不含最后BATCH.BIN自身写入、JTAG配置、电脑导出/导入和搬卡时间。不能将算法比称为全任务端到端加速比。

## 文件与构建

板上读取 `INDEX.BIN` 与 `IN/I0000001.BIN` 等文件，写入 `OUT/O0000001.BIN` 原始图像、`R0000001.BIN` 计时/校验记录，整批结束写BATCH.BIN。板上使用8.3文件名；原图片路径和配对信息放在电脑侧TASK.JSON。

构建顺序：已有相同Q14 HLS IP → `python -B build_hardware.py` → `vitis -s create_sd_bsp.py` → `python -B build_sd_firmware.py`。本机已完成构建；sd_bsp、sd_linker_script及工具路径放在settings.local.json。通用源码不包含AMD工具/BSP、数据集、bit/XSA/ELF或机器私有设置。

硬件引脚依据厂家《Z15 ZYNQ之嵌入式Vitis开发指南V1.2》277–279页及micro_sd_rw参考工程：SD0 MIO40..45，CD MIO10，BANK501 1.8V。仅增补SD相关PS配置，保留DDR 1GB与原PL计算结构。

## 容量预检查与保存位置

导出前按处理尺寸估算输入BIN、输出BIN、计时记录和文件系统余量；不足时不会生成任务文件。若导出中存储空间发生变化，程序仅撤销本次创建的半成品，保留输入原图和已有归档结果。

保存到可移动卡时必须选择盘符根目录，例如E盘；不能选择DHZRUN02等归档文件夹或DEHAZE本身。程序自动创建E:/DEHAZE。保存到电脑本地准备目录仍允许选择普通文件夹。

本机32GB卡当前电脑可见分区约130MB，其余是原Linux分区。暂不调整分区时先用只有2–5张图片的小文件夹试完整流程。改名保存的原任务仍占卡内空间；需要大批量时应另行规划容量，不能把JPG压缩文件大小当作输入＋输出BIN所需空间。
